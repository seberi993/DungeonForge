# Errors

Generated by `ErrorsDocTests` from the error catalog. Do not edit by hand: change the spec, the `[CoversError]` test or the
operation constant, then run `UPDATE_ERRORS_DOC=1 dotnet test --filter ErrorsDocTests`.

Every non-2xx response except the waiting 409 is `application/problem+json` with `code`, `operation`, `parameters` and
`traceId`. A 400 also carries `errors` (field to messages). A handler with no failure path may return its value directly.
The waiting 409 is a success variant: `{ partyId, locked, required, lockStatus, status: "waiting" }`, no code.

To trace a failure: code -> `ErrorCodes` constant -> its `ErrorSpec` (the "Defined in" file) -> the handler that returns it ->
the covering test. Search the code string to land on all of them.

## Log events

Failures outside a request's reply are coded log events, not errors: see `src/DungeonForge.Api/Errors/LogEvents.cs`.
Each has a stable `EventId` and `EventName` and is logged inside an `Operation`/`PartyId`/`Turn` scope.
